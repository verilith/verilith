# What verilith-server trusts

Beyond what every Verilith crate trusts (Verus, Z3, rustc, the specs: here
verilith-http's `spec.rs`, whose response grammar and framing rules the
serializer is proven against):

| File | What it is | What the rest assumes of it |
|---|---|---|
| `src/sys/mod.rs`, `linux.rs`, `macos.rs` | One-call wrappers over `socket`, `bind`, `listen`, `accept4`/`accept`, `read`, `writev`, `close`, `epoll_*`/`kqueue`, `sched_setaffinity`, `time` | `read_into` returning `Done(n)` wrote exactly `buf[..n]`, `n <= buf.len()`; `write_slices` returning `Done(n)` wrote the first `n` bytes in order; `sendfile_nb` returning `Done(n)` sent the next `n` bytes of the file range; a sealed memfd's contents cannot change; events name the token a socket was registered with; closing a socket's only descriptor also removes it from the poller |
| `src/sys/uring.rs` (Linux, `--io-uring`) | io_uring: `io_uring_setup`, `io_uring_enter`, the shared rings, a provided-buffer ring; entries for multishot accept and receive, `send`, `sendmsg`, `poll`, cancel | Memory a submitted entry names (a receive buffer, a send's bytes, a `msghdr` and its `iovec`s) stays valid and unmoved until its completion; each entry completes once (multishot: until a completion without `more`), with its `user_data`; a receive's bytes are in the provided buffer its completion names |
| `src/worker_uring.rs` (Linux, `--io-uring`) | The io_uring event loop | As `worker.rs`; and at most one receive and one send in flight per connection, the engine run only while no send is in flight, a slot (boxed) freed only after its last entry completes; tested against the epoll loop in `tests/uring.rs` |
| `src/worker.rs` | The event loop | Hands each connection's bytes to its engine once and in order, and writes the engine's output in order; one connection per slot |
| `src/h1.rs` | Runs handlers between the verified engine's calls (`out.rs`: `Engine::step`, `Wire::answer`, `Engine::finish`) | Writes only into `rbuf[end..]` (the slice `read_buf` returns) between engine calls, and changes the engine's `core` only through `Engine` and `read_buf`'s `compact`/`grow`/`filled`; what is answered, in which order and with which framing and persistence is the verified engine's |
| `src/out.rs` `Out::grew` | Lets `h2.rs` serialize frames straight into the output buffer | Between reading `buf.len()` and calling `grew`, the caller only appends to `buf` (`h2.rs`; the HTTP/1.1 path never calls it from outside `out.rs`) |
| `src/conn.rs` trusted wrapper | `decode_in` (`chunked::decode` on `&mut v[from..end]`) | It is the one call it names; the rest of `conn.rs` is verified (`shift_down`, `grow_zeros` and `vec_zeros` against vstd's specs of `copy_within`, `resize` and `vec!`) |
| `src/h2.rs` | The HTTP/2 engine's buffers, HPACK calls and handlers around the verified core (`h2core.rs`) | Hands every parsed frame (and parser error) to `Core` in order; feeds each `Step::Fragment` to the HPACK decoder in order and calls `Core::end_block` at END_HEADERS, with `request_fields` of the decoded fields (whether they are a valid request, and the Content-Length they declare, parsed by verilith-http's verified `content_length_exec`); touches a stream only through `Core::val`, and charges DATA only through `Core::take`; tested in `tests/h2.rs` |
| `src/tls.rs` (`--features tls`) | moving bytes between the socket, verilith-tls and the engines; PEM decoding of the certificate and key (and, with `--client-ca`, the CAs); handing the client's checked certificate to the engines for `Request::client_certificate` | the handshake, key schedule, record layer and client certificate check are verilith-tls's, verified; `tls.rs` only buffers and moves bytes and is tested in `tests/tls.rs` (every ciphertext split, both ALPN protocols, both backends; `client_certificates` over HTTP/1.1 and h2) |
| verilith-tls-aws-lc (aws-lc) | TLS cryptography: AEAD, key exchange, signatures, random numbers; with `--early-data`, the 0-RTT anti-replay register; with `--ech`, HPKE; with `--client-ca`, signature verification of client certificates and CertificateVerify, and the UTC clock for validity | each function meets the contract on verilith-tls's `Provider` trait; aws-lc is the cryptography OpenSSL-class servers trust, with proofs of its own for several primitives; ticket sealing and HPKE's ChaCha20-Poly1305 are libcrux's (HACL*, verified) and HPKE's HMAC verilith-sha2's. Which primitive comes from where, and what proof covers it, is in [tls-aws-lc/CRYPTO.md](../tls-aws-lc/CRYPTO.md). `claim_early` is the clock, a lock and the binder's first 16 bytes around verilith-tls's `antireplay::Register::claim`, which is verified to take a ClientHello's early data at most once and only within the 10 s freshness window (in this process only). With `--ech`, HPKE (RFC 9180) opening the encrypted ClientHello: `ech_open` returns only what a client sealed to the server's ECH key with that additional data, checked against rustls's HPKE in `tls-aws-lc/tests/hpke.rs`. With `--client-ca`, `verify_cert_sig` and `verify_tls_sig` say yes only for a valid signature by that key with that algorithm (aws-lc's ECDSA, Ed25519, RSA), and `now_utc` is the system clock; tested with rustls clients in `tls-aws-lc/tests/client_auth.rs` |
| `src/h1.rs`, `src/h2.rs` 0-RTT gate | answering 425 Too Early, instead of calling the handler, when the verified `early::too_early` says so (early data and a method other than GET, HEAD or OPTIONS), and setting `Request::early` | tested in `tests/tls.rs` (`early_data_http11`, `early_data_h2`) |
| rustls (`--features tls-rustls`, `--tls-backend rustls`) | a second TLS backend, for comparison | off unless chosen; trusted as any TLS library |
| `src/h3.rs` (`--features h3`) | The HTTP/3 glue: accepts QUIC streams, hands their bytes to the verified core (`src/h3core.rs`), QPACK-decodes the sections the core points at and encodes responses (verilith-qpack), dispatches handlers, writes responses | Feeds each stream's bytes to its `Req3`/`Uni3` once and in order (a reset stream as its end), decodes exactly the `Src` the core returns, passes each decoded `content-length` value to `Req3::declare_cl`, dispatches only on `Act::Ready` and refuses on `Act::Malformed`, sends `frame_head`'s bytes then the body, feeds QPACK streams exactly `input[from..]` of `UAct::Raw(from)`, and charges `Budget` for every abandoned or refused request stream; what each stream means, the error codes, our SETTINGS and the response framing are `h3core.rs`'s, verified; tested in `tests/h3.rs` |
| verilith-quic-conn (`--features h3`) | QUIC on verilith-quic (wire format, flow control, stream states, loss recovery, congestion control: verified) and verilith-tls (QUIC handshake, packet and header protection: verified) with aws-lc | Its connection logic, joining those pieces, is plain Rust and not yet verified (its README); tested against quinn's client in its `tests/quinn.rs`, and under `tests/h3.rs` here |
| `sys::bind_udp`, `recv_from`, `recv_gro`, `send_to` | `socket`/`bind`, `recvfrom`, `recvmsg` with UDP_GRO, `sendmsg` with UDP_SEGMENT (Linux GSO) | `recv_from` and `recv_gro` returning `n` wrote `buf[..n]` (for `recv_gro`, datagrams of the `seg` bytes the kernel reported, back to back); `send_to` sends `buf` as datagrams of `segment` bytes, or drops them (QUIC recovers) |
| `sys::open_beneath` | `openat2(RESOLVE_BENEATH \| RESOLVE_NO_MAGICLINKS)` on Linux; `openat(O_NOFOLLOW)` per component elsewhere | The kernel resolves no `..` or symlink outside the root (Linux), or follows no symlink at all (the fallback); the path given is `path.rs`'s, proven to have no `.`, `..`, empty or NUL component |
| `src/files.rs` | The static file server around the verified path and range functions | Opens only paths `resolve_exec` returned, joined by `join_to`; serves only ranges `parse_range` returned; the cache, validators and media types are plain Rust, tested in `tests/files.rs` |
| `src/date.rs` | `Date` formatting | Writes 29 bytes of IMF-fixdate; the value is checked by the verified `check_value` before it is sent, so a bug here cannot split a response |
| `src/lib.rs` | The handler API | Passes handler fields to `write_head_checked` and nothing else to the wire |
| `src/bin/verilith-server.rs` | The benchmark server's routes | Application code |

`scripts/trust-ledger.py` counts these files in the root
[TRUST-LEDGER.md](../../TRUST-LEDGER.md).
